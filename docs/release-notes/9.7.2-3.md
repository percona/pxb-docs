#  Percona XtraBackup 9.7.2-3 (2026-11-26)

Get started with [Quickstart Guide for Percona XtraBackup].

## Release highlights

Percona XtraBackup 9.7.2-3 supports backing up Percona Server for MySQL 9.7.x and MySQL 9.7.x.

Use the Percona XtraBackup 8.4 series to take backups of Percona Server for MySQL 8.4.x and MySQL 8.4.x series.

Percona XtraBackup 9.7.2-3 adds support for the Hierarchical Navigable Small World (HNSW) vector indexes introduced in Percona Server for MySQL 9.7.4-4. If you use Percona XtraBackup 9.7.2-2 or earlier to back up a Percona Server for MySQL 9.7.4-4 server that has tables with vector indexes, the backup can be incomplete or fail. To back up tables with vector indexes, use Percona XtraBackup 9.7.2-3. For details, see [Vector index](../server-backup-version-comparison.md#vector-index).

We recommend that you download the Percona XtraBackup for the same platform as the MySQL-compatible server. For example, if your server is on an ARM64 platform, you should download and use the Percona XtraBackup for ARM64 for that operating system.

Percona XtraBackup 9.7.2-3 release includes new features and bug fixes.

## New features

* [PXB-3915](https://perconadev.atlassian.net/browse/PXB-3915): Adds support for backing up tables with Hierarchical Navigable Small World (HNSW) vector indexes in Percona Server for MySQL 9.7.4-4. Percona XtraBackup now recognizes the redo log record type that Percona Server for MySQL writes for tables with vector indexes and supports the backup, prepare, and restore steps for these tables. Before, when the redo log contained a write to a table with a vector index, the backup stopped with a corrupt log record error and copied no data. `xtrabackup --prepare --export` no longer terminates unexpectedly on a table with a vector index and creates the `.ibd` and `.cfg` files for the table. However, Percona Server for MySQL 9.7.4-4 does not allow the import of tables with vector indexes. For details, see [Vector index](../server-backup-version-comparison.md#vector-index).

## Bug fixes

* [PXB-3889](https://perconadev.atlassian.net/browse/PXB-3889): Fixed an issue where `xtrabackup --prepare --use-free-memory-pct` terminated unexpectedly with a segmentation fault on operating systems that use `libproc2`, such as RHEL 10, Debian 12 and 13, and Ubuntu 24.04. (Thank you to Alexander Olekhnovich for your contribution)

* [PXB-3894](https://perconadev.atlassian.net/browse/PXB-3894): Fixed an issue where `xbcloud get` failed on Azure Blob Storage containers with Hierarchical Namespace (HNS) enabled. `xbcloud` parsed directory entries as backup chunks, which caused the get operation to fail.

* [PXB-3930](https://perconadev.atlassian.net/browse/PXB-3930): Fixed an issue where the Percona XtraBackup 9.7.2-2 DEB packages did not include the `/usr/bin/xtrabackup-debug` binary and the unversioned `libprotobuf-lite.so` symbolic link. The main `xtrabackup` binary was not affected.

* [PXB-3932](https://perconadev.atlassian.net/browse/PXB-3932): Fixed an issue where `xtrabackup --prepare` of an incremental backup taken with page tracking terminated unexpectedly with an assertion failure or a segmentation fault. The issue occurred when a vector index (HNSW) auxiliary tablespace was created after the full backup.

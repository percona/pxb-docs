#  Percona XtraBackup 9.7.2-2 (2026-11-)

Get started with [Quickstart Guide for Percona XtraBackup].

## Release Highlights
 
Percona XtraBackup 9.7.2-2 supports backing up Percona Server for MySQL 9.7.x and MySQL 9.7.x.
 
Use the Percona XtraBackup 8.4 series to take backups of Percona Server for MySQL 8.4.x and MySQL 8.4.x series.

We recommend that you download the Percona XtraBackup for the same platform as the MySQL-compatible server. For example, if your server is on an ARM64 platform, you should download and use the Percona XtraBackup for ARM64 for that operating system.
 
Percona XtraBackup 9.7.2-2 release includes new features, improvements, deprecations, and bug fixes.

### Renamed options

Percona XtraBackup 9.7.2-2 renames the following options. The new names describe the phase or the action of each option more clearly.

| Deprecated name | New name | Used with |
| --------------- | -------- | --------- |
| `--apply-log-only` | [`--apply-redo-only`](../xtrabackup-option-reference.md#apply-redo-only) | `--prepare` |
| `--incremental-basedir` | [`--backup-incremental-base`](../xtrabackup-option-reference.md#backup-incremental-base) | `--backup` |
| `--incremental-dir` | [`--prepare-incremental-from-dir`](../xtrabackup-option-reference.md#prepare-incremental-from-dir) | `--prepare` |

Percona XtraBackup still accepts the old names but prints a deprecation warning at startup. If you pass an old name and its new name in the same command, Percona XtraBackup reports an error and does not start. A future Long-Term Support (LTS) release will remove `--apply-log-only`. A future release will remove `--incremental-basedir` and `--incremental-dir`. Update your scripts to use the new names.

### Deprecated options

Percona XtraBackup 9.7.2-2 deprecates the following options.

| Option | Use instead |
| ------ | ----------- |
| `--create-ib-logfile` | No replacement. The option has no effect. |
| [`--innodb`](../xtrabackup-option-reference.md#innodb) | No replacement. The option has no effect. |
| [`--log`](../xtrabackup-option-reference.md#log) | No replacement. The option has no effect. |
| [`--no-version-check`](../xtrabackup-option-reference.md#no-version-check) | No replacement. The option has no effect. |
| `--rebuild-threads` | No replacement. The option has no effect. |
| [`--rsync`](../xtrabackup-option-reference.md#rsync) | [`--lock-ddl=REDUCED`](../xtrabackup-option-reference.md#lock-ddl) |

Percona XtraBackup still accepts the options but prints a deprecation warning at startup. A future release will remove the options.
 
## New features
 
* [PXB-2559](https://perconadev.atlassian.net/browse/PXB-2559): Adds the `--history-host`, `--history-port`, `--history-socket`, `--history-user`, `--history-password`, and `--history-ssl-*` options to [store the backup history on a different server](../store-backup-history.md#store-backup-history-on-a-different-server). Before, Percona XtraBackup always wrote the history record to the server you back up. The write failed when that server ran with `super_read_only` enabled, for example, a replica or a secondary member of a single-primary Group Replication cluster. The `--incremental-history-name` and `--incremental-history-uuid` options also read the base LSN from the history server.

## Improvements
 
* [PXB-3502](https://perconadev.atlassian.net/browse/PXB-3502): Improves parallel processing performance. With `--parallel`, Percona XtraBackup now processes files in largest-first order instead of discovery order. Large tables and partitions start processing earlier, so you spend less time waiting for large files after other parallel tasks complete. The improvement applies to `--backup`, `--prepare --prepare-incremental-from-dir`, `--copy-back`, `--move-back`, and `--decompress`.

* [PXB-3758](https://perconadev.atlassian.net/browse/PXB-3758): Adds the [`--apply-redo-only`](../xtrabackup-option-reference.md#apply-redo-only) option as the new name for `--apply-log-only`. Both names work the same way. If you pass both options in the same command, Percona XtraBackup reports an error and does not start. For details, see [Prepare an incremental backup](../prepare-incremental-backup.md).

* [PXB-3840](https://perconadev.atlassian.net/browse/PXB-3840): Adds phase-specific names for the incremental backup options. Use [`--backup-incremental-base`](../xtrabackup-option-reference.md#backup-incremental-base) instead of `--incremental-basedir` with `--backup`. Use [`--prepare-incremental-from-dir`](../xtrabackup-option-reference.md#prepare-incremental-from-dir) instead of `--incremental-dir` with `--prepare`. The old and new names work the same way. If you pass an old name and its new name in the same command, Percona XtraBackup reports an error and does not start.

## Bug fixes
 
* [PXB-3609](https://perconadev.atlassian.net/browse/PXB-3609): Fixed an issue where `xbcloud delete` did not remove the `.md5` checksum files for backups uploaded with `xbcloud put --md5`.

* [PXB-3800](https://perconadev.atlassian.net/browse/PXB-3800): Fixed an issue where `xtrabackup` terminated unexpectedly with an assertion failure in `fil_tablespace_redo_extend()` when the redo log contained an `MLOG_FILE_EXTEND` record for the system tablespace.

* [PXB-3853](https://perconadev.atlassian.net/browse/PXB-3853): Fixed an issue where incremental backups with page tracking read the unchanged pages between blocks of changed pages. On large tablespaces, the incremental backup could read nearly the whole file. Percona XtraBackup now skips the unchanged page ranges between blocks of changed pages. (Thank you to Reto Giezendanner for your contribution)

* [PXB-3862](https://perconadev.atlassian.net/browse/PXB-3862): Fixed an issue where incremental backups with page tracking were slow when a tablespace had scattered changed pages. Percona XtraBackup read each scattered changed page on its own, and thousands of small reads take much longer than a few large reads. Percona XtraBackup now reads nearby changed pages together when reading the unchanged pages between them costs less than another read. Percona XtraBackup measures your storage at the start of the backup, so you do not need to change the configuration. The backup contents and size stay the same. Use the new [`--page-tracking-merge-gap`](../xtrabackup-option-reference.md#page-tracking-merge-gap) option to set a fixed gap, or set the option to `0` to turn off the behavior. For details, see [Read scattered changed pages](../page-tracking.md#read-scattered-changed-pages).

* [PXB-3863](https://perconadev.atlassian.net/browse/PXB-3863): Fixed an issue where `xbcloud put`, `xbcloud get`, and `xbcloud delete` could fail on Azure Blob Storage containers with hierarchical namespace enabled when the backup name began with a slash, for example, `xbcloud put /db/hns`. Percona XtraBackup now handles leading slashes correctly.

* [PXB-3885](https://perconadev.atlassian.net/browse/PXB-3885): Fixed an issue where `xbcloud` ran the retry waits of parallel requests one after another when the network was slow or unavailable. As a result, several failed requests took the sum of their backoff delays instead of the longest delay. The waits now run at the same time.

* [PXB-3882](https://perconadev.atlassian.net/browse/PXB-3882): Fixed an issue where the debug build did not compile with gcc 15.2.
